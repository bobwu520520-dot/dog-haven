### 10. 写实立绘接入 Canvas 渲染管线（1.2 收集亮点 · 视觉升级）

**背景**：`assets/art/*.jpg` 此前只在图鉴弹窗以 `<img>` 展示，Canvas 内的狗狗是纯矢量绘制 —— 即「图鉴里是写实插画、场景里是矢量卡通」，同一条狗有两副长相。本次把立绘接进 Canvas，使其成为场景与头像的统一长相来源。

- **新增 `js/sprite.js`（`DogSpriteLoader`，199 行）**：8 张立绘是**纯白底平面插画、无透明通道**，直接贴到草地上会是一个白色方块。本模块在运行时完成三步处理：
  1. **抠底**：从图片四边向内做**洪水填充**，只把「与边界连通的近白像素」置透明。用连通区域而非全局阈值，是为了**保住狗狗身上本身的白色毛色**（萨摩耶、柯基白胸、边牧白脖圈），避免被一并抠成透明洞。
  2. **羽化**：与透明区相邻的浅色像素按白度衰减不透明度，消除抠图残留的白色描边。
  3. **量包围盒**：统计 alpha 包围盒，供场景等比缩放定位与头像头部裁切复用。
  - 结果按 `src` 缓存，8 只狗共享同一份处理结果，仅在首次加载时计算一次。
- **`js/dog.js` · 场景立绘渲染**：
  - 新增 `useSpriteRenderer()` / `spriteSupportsPose()` 分支判定：立绘就绪 → 走立绘分支；未就绪 → **自动回退矢量分支**（首帧不会白屏或报错）。
  - 新增 `drawSpriteFigure(ctx)`：以「**脚底贴地**」为锚点做等比缩放定位（底边落在 `SPRITE_FEET_Y = 22`，与矢量管线的脚掌 y≈+20、地面阴影 y=24 对齐），避免立绘「飘在地面上方」；并支持水平镜像表达 `facing`。
  - 立绘接管长相后，矢量管线的尾巴/身体/头耳/脸/衣物**整体让位**，否则会出现「立绘一只狗 + 矢量第二只狗」的重影。
- **逐犬种朝向校正（本次修掉的一个真实 bug）**：
  - 早期实现把素材朝向默认写成「一律朝右」，但 8 张素材**朝向分两派** —— 金毛/边牧/萨摩耶/拉布拉多朝左，柴犬/柯基/哈士奇/法斗朝右。
  - 而 `facing = 1` 在全局约定里表示「向右移动」（`facing = dx > 0 ? 1 : -1`），于是朝左那 4 只**全程倒着走**。
  - 现改为 `SPRITE_TUNING` **逐犬种显式声明** `artFacing`，不再依赖单一全局默认值。
- **毛色染色改为离屏合成（本次修掉的第二个真实 bug）**：
  - 原实现直接在**主画布**上 `fillRect` + `globalCompositeOperation = 'source-atop'` 叠加色相。`source-atop` 按「**目标 alpha**」生效，而主画布此时已被草地/工位铺满，于是**整块矩形都被染色**，草地上出现一个明显的方形色块（已用截图确认）。
  - 现改为在**离屏 canvas** 上先绘制立绘、再以立绘自身 alpha 为遮罩染色，最后把合成结果缓存为「染膏版立绘」（`_tintCache`，键含毛色 id）。染色只发生一次、每帧零成本，且**不可能溢出狗狗剪影**。
  - 毛色变更时 `invalidatePortrait()` + 清空 `_tintCache`，保证重算。
- **图鉴头像改为立绘头部特写**：
  - 问题：图鉴/名册头像只有 46px，把**整只狗**缩进去后五官完全不可辨，而图鉴恰恰是要看脸的。
  - 新增 `_spriteHeadBounds()`：先在上部 45% 横带内比较左右两半的前景像素数**判出头在哪一侧**（头比尾巴厚实），再在该侧取框并换算回局部坐标；取正方形、留 10% 余量，兼容左右两种朝向。
  - 头像与场景**共用同一套立绘定位映射**，不会出现「场景立绘 / 图鉴矢量」的割裂。

### 两个 CDP 验证脚本的健壮性修复
- **自起静态服务器**：`cdp_verify_gaps.js` 原先依赖外部在 `:8099` 起服务，而项目自带 `serve.js` 用的是 `:8089` —— **开箱即跑不起来**。现两个脚本都改为自带静态服务器，消除该前置依赖。
